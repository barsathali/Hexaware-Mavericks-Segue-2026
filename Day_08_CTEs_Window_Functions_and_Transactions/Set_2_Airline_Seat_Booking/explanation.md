# Airline booking explanation
READ COMMITTED prevents dirty reads but a normal read does not reserve a seat until transaction end. Competing sessions may both observe AVAILABLE unless a locking/constraint strategy is used. A unique constraint on (FlightId, SeatNo) is a final integrity guard. SERIALIZABLE plus UPDLOCK/HOLDLOCK makes the second request wait; after the first commits, it sees BOOKED and is rejected. RANK assigns tied rows the same rank and leaves gaps; DENSE_RANK assigns tied rows the same rank without gaps. MongoDB transaction updates the seat document and inserts booking document atomically; requires a replica set or sharded cluster.
